# v0.4.0

## 新增

- 加入需明確按接收角色啟用的 Claude AskUserQuestion 安全閘門。透過同步 Hooks 記錄問答生命週期，減少只依賴終端畫面狀態辨識的風險。
- 新增 `claude-guard --role ROLE enable|disable|status` 與 `claude-hook --role ROLE [--pane ID]`。
- 投遞前核對 session、pane、待答工具呼叫，以及最新 Herdr 狀態；安全閘門未通過時訊息保持 queued，不建立投遞批次。
- Hook 狀態寫入與通知提交共用本地角色鎖，縮小問答啟動與提交交錯的時間窗。
- 新增 CLI 指令總覽、雙語說明、可選 Hook 設定與隔離測試。

## 發布前審核修正

- 未建立角色政策目錄時，合法 Hook 事件為不寫檔的 no-op；已有目錄但政策缺失或損毀仍保守阻擋，不將錯誤當停用。
- 政策必須明確包含 `version: 1` 與布林 `enabled`；拒絕缺漏、null、型別錯誤、不支援版本、未知或重複欄位，避免 fail-open。
- 可選 Hook 範例以子 shell 執行並統一將啟動／非零結束失敗轉為 exit 2；保留 stdin 與引號邊界。整個 handler 被中止、逾時或未被呼叫仍不保證保護有效。
- 安裝範例與功能文件改以 v0.4.0 為版本基準，不宣稱已取得最終審核或已發布。

## 相容性與啟用

- 閘門預設不啟用，未設定角色維持原有投遞行為；有合法角色／環境的共用 Hook 也不會隱含啟用 guard。
- 未發布原型的無版本政策不自動遷移；查核會話後明確 disable／enable，再以新的 SessionStart 綁定，不可藉重置繞過未回答問題。
- 沒有佇列 DB migration，也沒有新增依賴。
- 不自動安裝 Claude Hooks，不自動修改 Claude 設定或重啟既有 worker。
- CLI 與運行中的 worker 都必須支援此版本；只更新 CLI 不會升級已運行的 worker。
- 啟用時必須明確設定同一個 root／state，並由真實 SessionStart 綁定角色；不應對已開啟的問答偽造 ready 記錄。

## 驗證範圍

- 開發階段已通過全量 `make check`、race tests、原生 CLI 合成事件測試及依賴一致性檢查；版本準備後仍須重新驗證並取得審核。
- 真實 Claude Code v2.1.308／Herdr 0.9.3 已觀察到：問答期間記錄 pending、通知保持排隊，親自選第二項後清除 pending，通知才送達。
- 該次 Herdr 正確回報 blocked，未重現 idle 誤判，不能將此測試當作原始問題已根治的證據。
- 通知確實出現在問答後，但 Claude 未依通知回覆指定確認文字；傳輸送達不等於訊息內容已被執行或接受。

## 已知限制

- 這是實驗性補強，不是 Claude 原生的原子狀態查詢／提交 API，也不保證杜絕所有競態。
- 僅涵蓋 AskUserQuestion，不涵蓋權限批准、ExitPlanMode、目錄信任或 MCP elicitation 等其他對話框。
- 取消或中斷未必有成對結束事件；缺少結束事件會保留阻擋，需人工確認，不以逾時自動解鎖。
- Hooks 未運行、被停用、啟動失敗或逾時時，既有 ready 記錄不能證明仍受保護。
- 真實取消／中斷、窄 pane 的 idle 誤判與鎖衝突仍未完成驗證。

設定、復原與限制詳見 [Claude question guard](../claude-question-guard.md)。
