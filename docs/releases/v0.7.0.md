# v0.7.0

## 重要行為變更：角色探索與身分宣告

- worker 先讀取 `herdr agent list`，將每個 agent 的絕對 `foreground_cwd` 與 relay root 解析為實體路徑；要求既存前景目錄嚴格位於 root 內，再取 basename 作角色名。中間目錄名稱、語言與深度不限，例如 `agents/reviewer` 或 `開発/担当A`。
- 不退回 shell `cwd`、不按固定角色容器或舊排名選座位。root 本身、無效／相對／不存在路徑、symlink 越界、無效 pane／狀態序號不投遞；同名座位即使只有一席 idle 仍視為衝突。
- 名稱以 Unicode 字母開頭，後續可為字母、組合符號、數字、底線或連字號，最多 64 UTF-8 bytes，不允許路徑分隔符、空白或控制字元。合法離線角色可先入列，不需預建角色目錄。
- 範例 `herdr-send.sh` 改為明確身分：優先 `HERDR_SEND_FROM`，其次 `HERDR_RELAY_FROM`，不再由 CWD 猜測；root 優先 `DELIVER_ROOT`。已複製的舊 wrapper 不會自動更新，須另核對啟動環境。

### 路由風險與信任邊界

角色是路徑推導的定址 key，**不是經驗證的座位身分**。root 內任意深度的合法同名目錄都參與定址，例如 `agents/gm` 與 `scratch/gm` 都是 `gm`：

- 同時存在會使訊息維持 queued，不任選其中一席。
- 原座位離線、只剩另一個同名座位時，該座位可接收 `gm` 訊息。
- 進入子目錄會改變角色名；symlink 使用實體 basename，而非連結名稱。

請選擇只含可信任座位的管理 root，避免過寬的 root、無關同名目錄及工作途中改變前景目錄。本版不新增固定層級、標記檔或白名單，也未做 Unicode NFC 正規化／同形字辨識；名稱需完全一致。本機 OS 帳號仍是信任邊界。

## 重要行為變更：缺省 Claude 攔截關閉

- 缺少 `team-policy.json` 時由 v0.6.0 的預設開啟改為**預設關閉**；讀取缺省不建立政策檔。**既有明確 `enabled:true` 或 `false` 完整保留**，損毀政策仍報錯，不默認為關閉。
- 關閉額外攔截時，已接線且有效的 Hooks 仍記錄事件與問答時間；不記錄問題／答案本文。關閉不回答問題、不清除 pending、不偽造 ready，Herdr 的 `blocked` 仍阻擋投遞。
- 啟用額外攔截仍要求有效 Hook／session 綁定；未初始化、問答中、unknown／ended 或讀取異常維持保守暫緩。角色探索成功或 submitted 不等於 Hook 初始化完成。
- Ctrl+P 的「全域／global」只指目前 relay root 共用政策，不代表整個 OS 帳號或其他專案。設定清單可列出即時角色及持久觀測，探索失敗會提示清單不完整，但仍可明確關閉政策。

## UI 改善

- 啟動時預設每秒自動刷新；`Ctrl+W` 停止／恢復，`r` 立即刷新。過期 timer 不會重新開啟已停止的刷新。
- Ctrl+P 改為兩行主題淡化提示，說明持續記錄問答時間，以及訊息阻塞時可診斷是否需要關閉額外攔截。移除觀測計數與 Hooks 健康提示，不把未初始化誤當成座位未上線。
- `?` 保留 14 個唯一快捷鍵，以 Browsing／Filters／Settings／Other（繁中：瀏覧／篩選／設置／其他）分組，小標題固定粗體；雙語、五主題、NO_COLOR 與窄畫面捲動均保留。

## 升級與回退

1. 發布、安裝 CLI、替換運行中 worker 與 Hooks 接線是不同操作。本版本不自動升級 worker、安裝全域 Hooks、重啟 AI、修改正式政策或處置佇列。
2. 升級前保存 DB、政策與角色觀測／pending 證據，在隔離 root／state 用同版本 CLI／worker 驗證。更新 CLI 或 UI 不會讓舊 v0.6.0 worker 自動採用新路由或缺省 off。
3. 核對 sender／root 環境、各座位前景目錄與同名衝突。舊 wrapper 若依賴 CWD 身分推導，須明確安排更新，不從資料夾或顯示名稱猜測發送者。
4. 缺少政策且需要額外保護的環境，應在有效 scoped Hooks／新會話已初始化並完成隔離驗證後，明確儲存 `--team enable`。既有明確啟用不受新缺省影響；不能靠切換開關或偽造 SessionStart 修復觀測缺口。
5. 回退 v0.6.0 時，缺少政策將重新變成預設 on，且舊路由限制會恢復，Unicode 或新目錄配置可能無法路由。v0.5.1 與更早版本則使用每角色 opt-in 並忽略團隊政策。先查核未完成問答、角色與佇列，保留證據並明確安排政策／路由，不盲目重送。
6. 無 DB migration、新依賴或 TCP listener；不因發布成功宣稱已部署或保護已生效。

## 驗證與限制

- 功能版本已通過獨立本地 sanity、Ubuntu／macOS CI（含 Python 3.12），涵蓋 Go race、44 項 Python／PTY、依賴一致性與固定 sqlc 產生碼檢查；版本準備提交與正式成品仍須分別核驗。
- 隔離假 Herdr／worker 整合涵蓋多語目錄、同名衝突恢復、重啟後佇列延續、root 邊界與缺省 off／明確 enable／disable。這不是所有真實 AI／Hooks 的完整端對端驗收。
- 真實 Claude 問答端對端、初始化／安全導入與所有終端的人工畫面驗收限制仍保留；不以角色探索或移除 UI 計數宣稱已修復。
- API 觀測仍可能包含非 Claude 角色；它是持久事件證據，不是 Hooks 健康心跳。問答保護只涵蓋 AskUserQuestion，不保證排除漏發 Hooks、其他授權對話框或 Herdr 快照與提交之間的競態。

完整操作與限制見 [角色與 SOP](../agent-usage.md)、[CLI](../cli-reference.md)、[UI](../ui.md) 及 [問答觀測與攔截](../claude-question-guard.md)。
