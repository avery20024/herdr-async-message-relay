# v0.10.0

## Highlights

- **Uncertain retry UI:** `status` now returns `retry_supported: true` and `queue_blocks: [{recipient, reason, batch_id, detail}]`. Select an uncertain batch in the TUI and press Ctrl+Enter → y to requeue all uncertain messages in that batch after reviewing the duplicate-delivery warning. Requires a matching worker; old workers disable the action. No schema migration.
- **y copy shortcuts:** Press y once to open a centered key guide, then yy/yi/yb/ys/yr to copy full body, message ID, batch ID, sender, or recipient. OSC 52 (XTGETTCAP Ms) is preferred; pbcopy with stdin is used as fallback. Does not require a worker upgrade or queue write.
- **Core delivery fixes:** three bugs affecting core backend delivery are resolved: (1) ForegroundCWD now falls back to the terminal's own CWD when the foreground process is unavailable (e.g., during a Claude Code restart), allowing `RoleFromAgent` to proceed to the Name check; (2) done→working status race after paste is now accepted as a valid confirmation outcome; (3) the core command timeout default is raised from 10 s to 30 s (overridable via `DELIVER_COMMAND_TIMEOUT_MS`) to prevent false uncertain results in worker environments without `HC_TERMINAL_SOCKET`.

## Upgrade and compatibility

1. Update the intended CLI and deliberately start a matching worker. The uncertain retry UI requires a worker on this version; the copy shortcuts work with any worker.
2. No queue migration, database schema change or new API field is required for existing queued/uncertain messages. Existing uncertain batches remain uncertain and can be retried using the new UI once the worker is updated.
3. The `DELIVER_COMMAND_TIMEOUT_MS` environment variable (1000–120000 ms) now overrides the per-command timeout for all backends. Core mode defaults to 30 000 ms when unset; legacy Herdr still defaults to 10 000 ms.
4. The three core delivery fixes are transparent; no operator action is required. Workers running against a core backend before this release may have recorded some batches as uncertain due to bug 1 (seat recognition) or bug 3 (timeout). Inspect and resolve those batches manually; the new worker will handle new deliveries correctly.

## Known limits

- Ctrl+Enter retry requires a terminal that distinguishes Ctrl+Enter from ordinary Enter (keyboard enhancement protocols). Ordinary Enter is never treated as a fallback.
- OSC 52 write acknowledgment is not dependable. The UI reports "request sent; paste to verify," not confirmed copy. A terminal or intermediary may still block it; there is no second attempt via pbcopy after an OSC request.
- Core delivery fixes apply to new delivery attempts only; messages already recorded as uncertain must still be manually resolved.
- The legacy Claude Hook interception control remains visible in core mode and may show Off instead of Unsupported. Do not use it as core protection.
