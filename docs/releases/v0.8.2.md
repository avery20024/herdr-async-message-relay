# v0.8.2

## 主要變更

- **UI單鍵回頂**：按`g`立即選取已載入第一筆，不再要求`gg`；`G`／Shift+g前往已載入最後一筆，均不因此額外分頁。保留晚到載入結果與視窗隔離。
- **分頁名稱定址**：以`tab_id`關聯Herdr agent／tab列表，只剝除開頭`[n] `顯示序號，依有效分頁名稱、有效agent名稱、實體前景目錄basename依序定址。同目錄可有不同完整名稱的獨立席位；高順位名稱取代低順位名稱，不保留別名。
- **觀測式Claude問答攔截**：啟用額外攔截後，只有匹配身份與啟動世代的已觀測`AskUserQuestion`開始事件才形成pending。首個PreToolUse即可建立觀測，不再要求先有SessionStart。匹配PostToolUse只解除自己的問題，多題需個別完成。焦點切到自由輸入或Herdr反覆回報idle，不會解除已知pending。
- **缺少觀測不再全面擋信**：無初始化、缺少／不符session或pane、觀測不可用時，不額外阻擋，仍遵守Herdr狀態及原有root／唯一席位檢查。觀測錯誤保留診斷；明確政策損毀、非法輸入或路徑仍報錯。未知phase本身不擋，但失敗不當作已知pending完成。
- **新增`claude-run`**：記錄啟動嘗試時間及隨機世代識別碼，再exec明確指定的命令；向子行程Hooks提供root、state、角色、pane、binary路徑及`HRELAY_CLAUDE_RUN_ID`。同session／pane重啟可排除舊pending，遲到舊Hook不能污染新紀錄；不依時鐘回撥或逾時解鎖。
- **恢復Ctrl+P開關**：重新顯示Claude interception (global)第三項與兩行淡化提示。開窗只讀政策，左右修改草稿、Enter儲存、Esc取消；未確認寫入須Ctrl+R重讀後再操作，不能盲目重試。預設仍off，既有明確政策保持不變。

## 升級與接線

1. CLI、UI、worker需使用對應版本；發布／安裝CLI不會替換健康中的worker，恢復UI開關也不代表新語義已在舊worker生效。服務切換需明確安排，勿因更新UI擅自重啟AI或正式worker。
2. 缺少team政策仍為off；升級不會強制將既有on改off。Scoped Hooks在停用額外攔截時仍記錄，只有實際阻擋投遞受政策控制。
3. 新啟動紀錄不是自動掃描器；要可靠識別同session／pane重啟，所有相關啟動與resume路徑都須經`claude-run`，且子行程須接好同root／state／角色／pane的Hooks。舊座位不會自動改接，不偽造SessionStart或ready。
4. 角色定址需唯一，foreground_cwd須實際位於root內。改分頁名稱會改收件地址，不自動遷移queued訊息、政策或Hook資料。新分頁拓樸查詢失敗、重複tab_id或關聯缺失時整輪延後；舊Herdr完全無tab_id時保留agent／目錄備援。
5. 保留state與事件證據再安排降版；舊版攔截語義不同，不以刪檔、重設或切換開關假裝問答已完成。

## 已知限制與風險

- **明確接受fail-open取捨**：Hook未接線、漏掉開始事件、觀測損毀或寫入失敗，可能在未回答問題時仍投遞。已記錄開始但漏掉完成事件則可能持續pending；沒有逾時自動解鎖。失敗／取消不保證有Post事件，不以PostToolUseFailure直接當完成。
- 只保護已觀測的AskUserQuestion；其他權限、信任或互動提示仍依Herdr。Herdr探索與prompt提交不是原子操作，不保證exactly-once或完整問答防護。
- 啟動標記記錄的是嘗試，不代表exec成功、AI ready或Hook健康。未包裝的同session／pane重啟不能可靠區分。
- 事件追加與state替換非單一交易，壞觀測保留供診斷，不自動覆寫／重播來解鎖。事件無自動輪替。
- 本地驗證涵蓋Go race tests、45個Python／PTY測試、假Herdr隔離worker及非模型fixture原生exec；尚未獨立重現原生Claude自由輸入焦點案例或完成真人畫面驗收，不將自動化結果當成實際AI問答驗收。
