# v0.8.0

## 重要行為變更：根目錄不再退回當前目錄

- 根目錄選擇順序為 `--root` → `DELIVER_ROOT` → 自當前目錄向上最近、含 `.hrelay` 標記檔的目錄 → 報錯。**不再單以當前目錄作為根目錄。**
- 過去未設定 `DELIVER_ROOT` 時，在 AI 座位的子目錄執行指令會把該子目錄當成根目錄，悄悄建立第二個 relay 實例；訊息因找不到座位而停在 queued。現在這種情況直接報錯並提示 `hrelay init`。
- 新增 `hrelay init [PATH]`：在團隊根目錄寫入 `.hrelay` 標記檔（只記格式版本、不記路徑），重複執行不覆寫，並印出 `DELIVER_ROOT`／`HERDR_RELAY_FROM` 範例。只認同名的一般檔案，目錄與符號連結忽略，也不以目錄名稱推測根目錄。
- 已用 `DELIVER_ROOT` 或 `--root` 的環境不受影響；變數優先於標記檔。
- 中英文 README 新增「團隊根目錄與實例」章節，說明根目錄 → 狀態目錄 → socket → 服務的對應。不同根目錄即不同實例，同一台機器可並行多個專案。

## 新增：實例管理

- `hrelay ps [--json]` 列出本機所有已登記實例（ID、狀態、根目錄），不受目前根目錄或 Herdr 環境影響。ID 為根目錄與狀態目錄雜湊的前 12 碼，後續指令可用至少 4 碼的前綴。
- `hrelay stop ID` 暫停並停止受管理服務、`hrelay start ID` 依已儲存設定恢復；兩者都保留登記與佇列。
- `hrelay rm ID` 停止並移除服務單元與登記，**佇列預設保留**；`--purge --confirm` 才刪除佇列資料庫、socket 與鎖檔，其他狀態檔（如問答攔截設定）不動。
- 非本插件管理且運行中的 relay 一律拒絕停止或移除。
- 同一根目錄以不同 `DELIVER_STATE_DIR` 重複登記會被拒絕，並指出既有 ID。

## 重要行為變更：Herdr 結束時 relay 自行退出

- 受管理的 relay 會監看登記時的 Herdr socket。確定沒有 listener（不存在或拒絕連線）連續 6 次（每 5 秒一次）後正常結束；逾時或權限錯誤不計入。
- 服務單元改為「正常退出不重啟」：launchd `KeepAlive` 改為 `SuccessfulExit=false`，systemd 改為 `Restart=on-failure`。當機仍會重啟。
- Herdr 啟動 hook 會執行 `service restore`，重新啟動已登記且未暫停的實例。relay 停止期間，訊息保留在佇列。

## 新增：以 agent 名稱決定座位角色

- 座位目錄名稱不是想收信的角色名時（例如任務 Worktree），可用 `herdr agent rename <pane> <name>` 命名，名稱即為角色；`--clear` 可清除。
- 有效名稱取代該座位依目錄得到的角色（目錄名稱不再收信）；名稱無效或為空則退回目錄名稱。前景目錄仍須嚴格位於 relay 根目錄內，名稱不能把其他專案的座位拉進來。
- 兩個座位宣稱同一角色時維持歧義，訊息留在佇列。任何有效名稱都會生效，固定座位請勿為了美觀而改名。

## 升級與回退

1. 發布、安裝 CLI、替換運行中 worker 是不同操作。本版本不自動升級 worker、不重啟服務、不處置佇列。更新 CLI 不會讓運行中的舊 worker 採用新行為。
2. 升級前先用 `hrelay ps`（升級後的 CLI）或 `hrelay service list` 核對已登記實例。已登記服務的單元檔會在**下次啟動該實例時**更新為新的重啟策略與 Herdr 監看；在那之前行為不變。
3. 依賴「在子目錄執行、未設 `DELIVER_ROOT`」的腳本會開始報錯。請在座位啟動環境設定 `DELIVER_ROOT` 與 `HERDR_RELAY_FROM`，或在根目錄執行一次 `hrelay init`。
4. 先前因根目錄錯誤而產生的多餘實例，可在新版 CLI 用 `hrelay ps` 找出，確認佇列內容後以 `hrelay rm ID` 整併；需要刪除佇列才加 `--purge --confirm`。
5. 回退 v0.7.0：`.hrelay` 標記檔會被忽略，根目錄再次退回當前目錄；已改寫的單元檔在重啟該實例前仍使用新策略。agent 名稱角色在 v0.7.0 無效，具名座位會恢復依目錄名稱定址。先查核佇列與座位，不盲目重送。
6. 無 DB migration、新依賴或 TCP listener；不因發布成功宣稱已部署或已生效。

## 驗證與限制

- 各功能 PR（#11、#12、#13）合併時 Ubuntu／macOS CI 全部成功；涵蓋 Go race、44 項 Python／PTY 與固定 sqlc 產生碼檢查。版本準備提交與正式成品仍須分別核驗。
- 實例管理與服務單元以假服務管理器測試。**尚未以真實 launchd／systemd 與 Herdr 驗證**「Herdr 結束後 relay 退出且不被重啟、Herdr 重啟後恢復」整段流程。
- 具名座位未以真實 Herdr 走完整投遞流程；僅確認 `agent rename` 會在 `agent list` 顯示 `name`。
- 無獨立 Reviewer 對 v0.8.0 各功能的審核紀錄。
