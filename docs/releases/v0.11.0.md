# v0.11.0

## Highlights

- **Cancel uncertain batches offline:** `hrelay cancel-uncertain --batch batch-ID` cancels an `uncertain` batch directly in the database without requiring the daemon socket. All messages in the batch transition to `canceled`; the batch is marked `resolved_submitted`. Use this when the daemon has been restarted and its old socket is gone.
- **Resend uncertain via direct hc send:** `hrelay resend --batch batch-ID` re-delivers an `uncertain` batch directly via `hc send --json` without re-queuing through the daemon. Requires the core backend (`HC_SOCKET` must be set). On success the batch transitions to `resolved_submitted` and all messages to `submitted`. Note: the original delivery attempt may already have reached the recipient; treat resent messages as potentially duplicate.
- **Pull queued messages:** `hrelay pull [--role role] [--limit N]` lets a seat proactively fetch messages queued for it, without waiting for the daemon to push them. The command atomically transitions matching `queued` messages to `submitted` and prints them to stdout in the standard batch envelope format. If `--role` is omitted the role is derived from the current working directory. The daemon does not need to be running.

## Upgrade and compatibility

1. These are CLI-only additions. No new daemon API endpoints, schema migrations, or worker-side changes are required.
2. Update the CLI binary (`hrelay service install` or manual copy) to make the three new commands available. The running daemon does not need to be restarted.
3. `hrelay resend` requires `HC_SOCKET` in the environment (core backend). Set it, or export it, before calling the command; the board-server `/hrelay/resend` endpoint reads `backend.json` and sets it automatically.
4. `hrelay pull` performs a direct database write. It is safe to run while the daemon is running; the atomic transaction prevents double-delivery.

## Known limits

- `hrelay resend` sends only the message bodies already stored in the batch. If the recipient's terminal address (pane) has changed since the batch was created, delivery fails with an address error.
- Resent messages may already have been delivered by the original attempt. Recipients should check message IDs to avoid acting on duplicates.
- `hrelay pull` pulls all matching `queued` messages (up to `--limit`). There is no filtering by sender or time range; use `hrelay list` to inspect before pulling if selectivity matters.
