# v0.9.0

## Highlights

- **Durable herdr-core delivery:** `hrelay send` commits to SQLite and returns an acceptance ID/key without waiting for the recipient. A separate worker discovers local core terminals and submits when an eligible role is ready. The adapter targets the **hc 0.1.21** CLI contract.
- **Explicit backend selection:** `HRELAY_BACKEND=auto|herdr|core`; a complete HC terminal context selects core automatically. Incomplete/conflicting contexts fail rather than silently falling back to legacy Herdr.
- **Independent state and services:** core binds canonical root, backend and core socket, with a separate default state path, registry namespace and OS service identity. The legacy Herdr backend remains available; queues are not bridged or migrated.
- **Verified sender declarations:** before service ensure or enqueue, the CLI checks its physical working directory, live selected-backend foreground directories and unique seat binding. Nonempty `--from`, `HERDR_RELAY_FROM` and `HERDR_SEND_FROM` must agree. Worktrees use verified bindings, not directory-name guesses; shared directories require a unique binding.
- **Conservative core uncertainty:** per-role FIFO, process-generation/turn fencing, bounded discovery/submission and up to four independent dispatch tasks. Any unconfirmed core submission is held as uncertain, with that recipient's later messages paused until authorized inspection/resolution. Other roles can continue.

## Upgrade and compatibility

1. Update the intended CLI and deliberately start a matching worker. Publishing or installing a binary does **not** replace a healthy worker, alter live AI environments, update an external direct-`hc send` wrapper or start an App integration.
2. For legacy Herdr, the plugin requires Herdr 0.9.3+. Core mode instead needs the supported hc executable/socket on the recipient machine, not the legacy Herdr executable. Native release archives cover macOS/Linux arm64 and amd64; there is no native Windows build or herdr-app Mod in this release.
3. Preserve real caller context. In core seats, keep valid `HC_TERMINAL_ID` and absolute `HC_TERMINAL_SOCKET`; any `HC_SOCKET` must match. Outside a seat, an authorized operator explicitly selects `HRELAY_BACKEND=core` and an absolute `HC_SOCKET`. Socket-only auto context is rejected. Do not unset caller bindings to evade errors.
4. Stale sender hints that older releases accepted can now fail before service creation/enqueue. Correct the launch/resume context through the team's handover process. The explicit outside-seat operator exception requires an authorized `--from`; environment alone is not sufficient. This is accidental-confusion protection, not authentication against a hostile process sharing the OS account.
5. Use separate backend state. Never point an old binary at core state, share an existing database across backends, delete `backend.json` to bypass a binding error or move old queued/uncertain messages merely to make the new backend work. `ps` and restore inspect the selected backend registry, not a combined inventory.
6. Core routes by valid **terminal name**, then the physical foreground directory basename strictly inside the root—not App tab labels/title/where. Full-address duplicates remain ambiguous even if only one is idle. Shells and agents without valid status/generation metadata remain queued; hrelay does not install OSC 7501 status reporting.
7. Core submission errors/timeouts can occur after a paste has taken effect. Do not automatically resend, change the idempotency key or assume killing a CLI canceled delivery. Inspect the recipient and exact message/batch IDs before an authorized resolve. Core automatic retry is disabled regardless of `DELIVER_MAX_ATTEMPTS`; the legacy Herdr retry policy is unchanged. `accepted` is persistence, `submitted` is transport confirmation, neither is a read/task-acceptance receipt or an exactly-once guarantee.

## Known limits

- **Core does not support legacy Claude Hook/claude-run interception.** It uses reported core status and hc's blocked-state protection. False-idle question/permission behavior is not established as fixed.
- **Known TUI limitation:** the legacy interception preference remains visible in core and can show Off instead of Unsupported; changing the core policy fails. Do not use the control or legacy Hook CLI as core protection. The separate capability-label/App Mod work is not included.
- Discovery and submission are not one atomic transaction with hc. Draft waits can outlast the bounded CLI deadline; uncertainty still requires evidence-based handling. Done-state races rely on hc's built-in blocked protection, with no force/keyboard fallback.
- Local `tN` terminals only; remote `machine/tN` recipients are excluded. Run the relay on their machine. Closing the App window is not equivalent to stopping core or its relay.
- Automated regression uses fake hc/service managers and isolated temporary databases/sockets. A separate basic live-core round trip was observed with isolated relay state; this is not full question, permission, draft, reconnect, OS lifecycle or human acceptance coverage.

## 繁體中文摘要

### 主要變更

- 新增依 hc **0.1.21** 介面的 core 持久佇列後端：SQLite commit 後先回接受結果，不等待收件席位；獨立 worker 待可投遞時送入。
- `HRELAY_BACKEND=auto|herdr|core`；完整 HC caller 環境可自動選擇 core，標記不完整或衝突拒絕，不退回舊同名角色。
- core state、registry 與 OS 服務依 root／後端／socket 隔離；舊 Herdr 後端保留，不搬移或橋接舊佇列。
- 發送 CLI 在 Ensure／POST 前交叉核對實體 pwd、即時前景目錄與唯一席位綁定；所有非空 sender 宣告必須一致，矛盾不再互相覆蓋。Worktree 依查證綁定，不取 basename 猜身份。
- core 維持同角色 FIFO、有界探索／投遞與程序世代／turn fence。結果不明一律 uncertain，不自動重送，保留該角色後續訊息；其他角色可繼續。

### 升級、相容與限制

- 發布／安裝不等於部署；需分別核對 CLI 與 worker，服務切換另行安排，不改既有 AI／外部 wrapper／SOP。core 模式不需要舊 Herdr，本版不含 App Mod、App startup hook 或原生 Windows binary。
- 舊 sender 提示或繼承的錯誤席位資訊現在可能拒送，應修正啟動／resume 環境，不清除真實 caller 繞過。人工離線例外仍需授權與顯式 `--from`；本機 OS 帳號仍是信任邊界。
- 勿重用舊 DB、刪 backend.json 繞過錯誤或讓舊 binary 指向 core state；舊 queued／uncertain 留原處，另核對處置授權。
- core 採終端 name／實體前景目錄備援，App 顯示名稱不是地址；重名不任選，缺狀態不猜 idle，也不替模型安裝狀態回報機制。
- core 逾時不代表取消，先查畫面／message／batch，再由獲授權操作者 resolve；不盲重送、不換 key。accepted 不等於已讀，submitted 不等於接單，沒有 exactly-once 保證。
- **core 不支援舊 Claude Hook 問答攔截。** TUI 仍可能把不支援顯示成 Off，變更政策會失敗；不要把舊開關、claude-run 或 claude-guard 當 core 防護。本版沒有夾帶尚未完成的能力提示／App Mod 工作。
- 自動化與基本真實 core 往返不等於全隊、問答／權限／草稿、重連、OS 服務或人工驗收通過。
